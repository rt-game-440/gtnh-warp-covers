## #5 覆盖板界面

- [ ] **从零配置跨维度流体传输**
  - 操作说明：`./gradlew runClient` 进入创造模式世界。主世界放一个装了水的 GT 储罐 A，下界放一个空储罐 B，各贴一块流体折跃覆盖板。在 A 上蹲下右键覆盖板面打开界面：点「新增频道」，输入名称，勾选「创建后直接连接」后确定，再点「输入」。到下界在 B 上打开界面，左键点刚才的频道连接，点「输出」。
  - 预期效果：两处界面都能打开（蹲下右键覆盖板面，或打开机器 GUI 后点覆盖板图标）；频道列表显示频道名、颜色方块和归属者；状态栏依次提示「已创建并连接频道」「已连接频道」；B 的储罐开始收到水，A 状态栏显示「传输中」；全程不发聊天消息。
  - 用户反馈：
- [ ] **新增频道弹窗与重名提示**
  - 操作说明：在同一界面再点「新增频道」，输入和已有频道相同的名字确定；再清空名称确定；最后点「取消」。
  - 预期效果：重名和空名都在弹窗内红字提示且不创建；取消后弹窗关闭，列表不变。
  - 用户反馈：
- [ ] **连接与断开、交互状态切换**
  - 操作说明：在频道页左键点已连接的频道，再点一次；连接后依次点「输入」「输出」「空」。
  - 预期效果：第一次点击断开（三按钮消失、状态栏「未连接」），第二次重新连接且交互状态回到「空」；三按钮中当前状态高亮，状态栏随之变化。
  - 用户反馈：
- [ ] **流体名单设置**
  - 操作说明：切到「设置」页，拿着水桶点流体槽，再从 NEI 拖一种流体到槽里；切换白名单/黑名单；点某条右侧的 × 删除；最后点清空按钮。
  - 预期效果：两种流体依次出现在名单（图标+名称），不重复添加；切换后标签显示白名单或黑名单；删除和清空立即生效；黑名单下被列出的流体不再传输，白名单下只传列出的流体，名单被挡时状态栏显示「被名单过滤」。

  - 操作说明：`./gradlew runClient` 进入创造模式世界。主世界放一个装了杂物的 GT 箱式缓存（或超级箱）A，再放一台输出槽有产物的 LV 机器 M，下界放一个空的箱式缓存 B；各贴一块物品折跃覆盖板，同一个物品频道，A、M 设「输入」（M 的名单改成空黑名单），B 设「输出」并改成空黑名单。再把一块覆盖板贴到 GT 物品管道上设「输出」试一次。

  - 预期效果：tooltip 显示频道与名单信息；重贴、放回、重进后频道、交互状态、名单和匹配 NBT 开关都在，传输照常。

  - 预期效果：三种覆盖板都有「输出优先级」「速率」「周期(tick)」三个输入框，文字不重叠、名单列表可滚动且没被遮挡；优先级可为负数；速率和周期输入负数变 0，`abc` 变 0，超大数夹到上限；重新打开后数值还在；提示里的「当前实际」值符合服务器上限和最短周期。

  - 操作说明：一个流体频道，一个输入端（水罐），三个输出端：A 优先级设 5，B、C 保持 0。给 A 设速率 100，保持默认周期，观察三个储罐的水量。

## #9 归属、身份与连接权限

- [ ] **新增频道按钮置灰（本项尚未在真实客户端运行过，请重点看）**
  - 操作说明：退出游戏，把配置文件 `limits` 类别的 `maxChannelsPerOwnerPerType` 改成 `1`，进入世界，给机器贴流体折跃覆盖板，在频道页新增一个频道；然后再看「新增频道」按钮并悬停。结束后改回 `0`。
  - 预期效果：新增第一个频道正常；之后按钮变灰，悬停提示「该类型的频道数已达服务器上限」，点击不弹窗；物品、能量频道不受影响；改回 0 后恢复。
  - 用户反馈：
- [ ] **列表只显示有权限的频道**
  - 操作说明：开一个局域网或开发服务器，用两个账号（`./gradlew runClient` 可开第二个不同用户名的客户端）。账号 A 新建频道，账号 B 打开覆盖板看频道列表；再用 ServerUtilities 让两人组队，A 新建频道后 B 再看。
  - 预期效果：不组队时 B 看不到 A 的私人频道；组队后 B 能看到并连接队伍频道，A 在入队前建的个人频道仍看不到、归属者仍显示 A。
  - 用户反馈：
- [ ] **退队后连接端立即断开**
  - 操作说明：接上一项，B 把覆盖板连到队伍频道并设成输入，然后 B 退出队伍，打开该覆盖板看状态栏。
  - 预期效果：传输立刻停止，频道断开，状态栏显示「连接者失权被断开」；名单、优先级、速率、周期仍在。
  - 用户反馈：
- [ ] **无权限者贴带配置的覆盖板**
  - 操作说明：A 把连着私人频道、配置过名单的覆盖板撬下，交给 B（陌生人），由 B 贴到自己的机器上并打开界面。
  - 预期效果：频道被断开，状态栏显示「贴上者没有连接权限」，名单等其余配置保留。
  - 用户反馈：
- [ ] **解散队伍后频道转给原队长**
  - 操作说明：A 是队长，队伍下有频道「主网」，A 本人也有一个同类型的个人频道「主网」；解散队伍后打开覆盖板看列表。
  - 预期效果：队伍的频道归到 A 名下并改名为「主网 2」，A 的连接端继续工作；原组员连接的连接端被断开，显示「连接者失权被断开」。
  - 用户反馈：
- [ ] **职位和结盟变化的复查**
  - 操作说明：账号 B 以盟友身份连接队伍频道后，账号 A 在 ServerUtilities 的队伍界面解除与 B 的盟友关系，等待 1 秒左右。
  - 预期效果：失去连接权限的连接端在约 1 秒内断开（这类变化 ServerUtilities 不发事件，靠每秒一次的定时复查）。
  - 用户反馈：
